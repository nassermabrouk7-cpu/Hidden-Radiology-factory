# Meta publishing status and OAuth setup

The previous version of this report contained credentials and deployment details. Those values have been removed. Do not put access tokens, app secrets, cron secrets, or Vercel values in reports or source control. Rotate any credential that was previously exposed.

## First-time Meta setup

1. In Meta for Developers, create or select the production app and add the Facebook Login / Instagram Graph API products needed by the linked Facebook Page and Instagram professional account.
2. Configure the app's privacy policy, data deletion instructions, valid OAuth redirect URI, and the required business verification / App Review permissions for the intended users. Request only the permissions needed for publishing: `pages_manage_posts`, `pages_read_engagement`, `instagram_basic`, and `instagram_content_publish`.
3. In the app's OAuth settings, allow the exact HTTPS callback URL for the authorization route that will be implemented in a later phase. Keep the app in development mode until test users, Page access, and the callback are verified.
4. Add these server-only values to Vercel Production after approval: `META_APP_ID`, `META_APP_SECRET`, and a notification recipient `META_TOKEN_ALERT_EMAIL`. Keep the existing Page and Instagram access-token values in their current secret store until a separately reviewed OAuth callback can replace them securely. Never place credentials in this repository.
5. Authorize a Facebook user who has the required Page access, request the approved permissions, exchange the short-lived user token for a long-lived user token, then obtain the Page token through the Page listing endpoint. Instagram publishing uses the token associated with that linked professional account and the approved Instagram permissions. Store token expiry and granted scopes from Meta's response.
6. A future OAuth callback must validate `state`, use the exact registered redirect URI, exchange codes server-side, check the resulting Page/account IDs and scopes, and securely replace stored tokens. A Page token cannot be refreshed merely by submitting the existing Page token again. Implement refresh/re-authorization, encrypted token storage, and an operator recovery flow before claiming automatic renewal.

## Current implementation limits

The token health endpoint checks Meta's Token Debugging API and returns only status values. It does not create, rotate, or renew tokens. Meta app credentials are required to debug a token. Email alerts use the existing Resend configuration when both sender and API key are present, and require `META_TOKEN_ALERT_EMAIL`.

The daily Vercel product publishing schedule remains unchanged. Meta health is checked before it runs; invalid, missing, or unavailable Meta credentials block only Facebook and Instagram. Telegram remains independent.
